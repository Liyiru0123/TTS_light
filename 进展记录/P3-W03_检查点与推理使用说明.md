加载后必须使用**与训练一致**的模型结构：

```python
import json, torch
from mini_multimodal.tts import TinySpeechFlow

cfg = json.load(open("configs/p3_w03_i004_supported_rate.json", encoding="utf-8"))
vocab = json.load(open(cfg["output_data"] + "/vocabulary.json", encoding="utf-8"))["vocab"]
model = TinySpeechFlow(
    vocab_size=len(vocab),
    text_cfg=cfg["text_encoder"],
    duration_cfg=cfg["duration"],
    condition_cfg=cfg["condition"],
    unet_cfg=cfg["unet"],
    t_max=int(cfg["container"]["t_max"]),
)
ckpt = torch.load(cfg["output_results"] + "/checkpoints/best.pt", map_location="cpu", weights_only=False)
model.load_state_dict(ckpt["model_state"], strict=True)
model.eval()
```

## 2. 完整推理（文本 → 波形）

冻结链（P3-W02 VAE + HiFi-GAN）通过 `load_frozen_chain` 加载，示例见 `scripts/p3_w03_capabilities.py`：

```python
from mini_multimodal.tts.cfm import text_to_token_ids, ode_infer
from mini_multimodal.tts.frozen_chain import load_frozen_chain
import torch

chain = load_frozen_chain(cfg, ROOT)
text_chars = list("红色三角形")          # 字符必须存在于 vocabulary.json
token_ids = torch.tensor(text_to_token_ids(text_chars, vocab), dtype=torch.long)
h = model.encode_text(token_ids)
d_pred = model.duration.predict_durations(h).long()   # 预测时长 [N]
H = model.regulator(h, d_pred)                        # 可能抛 DurationOverflowError
C = model.condition_frames(H)
T = int(d_pred.sum().item())
x1 = ode_infer(model, C, T, t_max=64, ode_steps=20)   # [80, 64]
mel = chain.decode_latent(x1.reshape(4, 20, 64))      # [80, 256]
wave = chain.synthesize(mel[:, : min(4 * T, 256)])[0, 0].numpy()  # 22.05kHz
```

## 3. 可推理的输入文字范围（词表）

### 3.1 词表来源与规模

本模型的发音能力**严格限于** `data/speech/p3_w03_tiny_tts_v1/vocabulary.json` 中的 **46 个字符**（另有 1 个 `<pad>`，共 47 项）。词表来自 P1 统一微型世界场景描述语言的闭集词汇（形状、颜色、大小、位置、数量等），由数据派生（DATA-SPG-001）时自动生成。

### 3.2 完整词表

| 类别 | 字符 |
|---|---|
| 数字与数量 | `1` `2` `3` `三` `五` `个` |
| 形状 | `圆` `方` `矩` `形` `角` `边` |
| 颜色 | `红` `橙` `黄` `绿` `蓝` `紫` `色` |
| 大小 | `大` `小` `等` |
| 位置 | `上` `下` `左` `右` `中` `央` `位` `区` `侧` `于` `域` |
| 关系/其他 | `是` `有` `的` `对` `见` `可` `第` `帧` `正` `象` |
| 标点 | `。` `，` `；` |

### 3.3 核心规则与常见陷阱

- **模型只能发音词表内字符**；词表外字符（如 `黑` `白` `灰` `青` `长` `高` `宽`）不在本模型能力范围内。
- ⚠️ **静默过滤陷阱**：`text_to_token_ids` 对词表外字符**不报错、直接丢弃**。例如输入 `黑色的三角形` 时 `黑` 被静默去掉，实际合成的是 `色的三角形`——这是推理时最常见的“输出内容与输入不一致”原因。
- 推理前应检查输入：

```python
def check_oov(text_chars: list[str], vocab: dict) -> list[str]:
    """返回输入中不在词表内的字符（模型将静默丢弃它们）。"""
    return [ch for ch in text_chars if ch not in vocab]

# 示例
print(check_oov(list("红色的三角形"), vocab))   # []  —— 全部可合成
print(check_oov(list("黑色的三角形"), vocab))   # ["黑"] —— 黑 将被静默丢弃
```

### 3.4 教学意义

词表就是本模型的**知识边界**：模型只能“说出”它见过（在词表里）的字。这与真实 TTS 一脉相承——真实系统词表更大（字表/词表/音素表），但同样存在 OOV（out-of-vocabulary）问题，工程上通过更大的词表、字—音转换（g2p）或 fallback 机制缓解。本模型的 46 字符闭集词表让学生能**亲手观察**“词表外字符被静默丢弃”这一 OOV 现象。

## 4. 边界与常见错误

| 情况 | 行为 | 处理 |
|---|---|---|
| 文本含词表外字符 | `text_to_token_ids` 静默过滤 | 保证字符在 `vocabulary.json` 中，或先过滤 |
| $\hat{T} > 64$（长文本） | 抛 `DurationOverflowError`（显式失败） | 教学点：真实 TTS 用 chunking/streaming；演示见能力样例 overflow |
| $\hat{T} < 4$（极短文本） | 生成过短 | 建议至少 2 个字符 |
| 解码后波形超长 | mel 裁剪到 $4\hat{T}$ 帧 | 与训练一致（容器 64 帧） |
| 波形幅度 | 无硬削波（最大 < 0.9999） | 若出现削波检查冻结链归一化 |
